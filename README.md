# アマデウスシステムアーキテクチャ（コアプロット）

本ドキュメントは、アマデウスプロトタイプのシステム要件とアーキテクチャ設計の概要を示す。目標は、1か月以内に、牧瀬紅莉栖の人格を備えたリアルタイム音声対話型AIアシスタントを構築することである。

## 1. システム構成要素（アマデウスの構造）

本システムは、独立したモジュール群として設計されており、個別のテストや将来のアップグレード（例：ローカルモデルを別のAPIに置き換えること）を可能にします。

### 1.1 ブレイン（LLMコアとメモリ）
- **役割:** 入力テキストを処理し、文脈を維持し、知識を呼び出し、人格に基づいた応答を生成します。
- **エンジン:** Groq Llama 3 API（`groq` SDK経由）
- **主な機能（現在導入済みのMLOpsアーキテクチャ）:**
    - 低遅延応答生成のためのストリーミング出力（`send_message_stream`）。
    - 牧瀬紅莉栖の人格を強制・固定化するシステムプロンプトの静的定義。
    - 複数ターン文脈のためのChatSession短期メモリ。
    - **【RAG (Retrieval-Augmented Generation) 統合】:**
        - ChromaDBを用いたローカルベクトルデータベースによる機密性の高い記憶域の構築。
        - Pandasのベクトル化演算を用いた、生データ（会話コーパス）の高速なクレンジング（欠損値・ノイズの除去）パイプライン。
        - コンテキストウィンドウの汚染を防ぐための「一時的（Temporary）なプロンプト注入と破棄を繰り返す」独自のRAGメモリ制御ロジック。
        - Q（ユーザー入力）とA（AIの回答）を結合して埋め込むContext Combination手法による検索精度（レトリーバル）の向上。
- **ファイル:** `AmadeusSystem/amadeus_core.py`, `cleanse_kurisu_corpus.py`, `insert_kurisu_memory.py`

### 1.2 耳（音声認識／STT）
- **役割：** ユーザーのマイクから音声を聴き取り、発話を検知してテキストに変換します。
- **エンジン：** Faster Whisper（ローカル推論）。
- **主な機能：**
    - (将来) 音声活動検出（VAD）の導入により、ユーザーの話し始めと話し終わりを認識。
    - (将来) ブレインの処理開始までの遅延を最小限に抑えるため、モデルサイズの最適化等を実施予定。
    - Pyaudioを用いたインメモリ処理を採用しラグの軽減化
- **ファイル:** `AmadeusSystem/amadeus_ear.py` 

### 1.3 口（テキスト読み上げ／TTS）
- **役割：** ブレインが生成したテキストチャンクを非同期キューで受け取り、音声合成と極低遅延のインメモリ再生を行う。
- **エンジン：** VOICEVOX (ローカルAPI) ※将来的にGPT-SoVITSへ換装予定
- **主な機能:**
    - **非同期キュー（マルチスレッド）:** 音声再生中もLLMの思考と出力をブロックしないプロデューサー・コンシューマー設計。
    - **PyAudio ストリーム常時開放（インメモリ再生）:** WAVファイルをディスク保存せずメモリ上（`io.BytesIO`）で展開。さらにPyAudioのストリームを常時開放することで、チャンクごとのOSプロセス起動ラグやデバイス初期化ラグを完全に排除した「超低遅延シームレス再生」を実現。将来のGPT-SoVITSチャンクストリーミングAPIと完全な前方互換性を持つ。
- **ファイル:** `AmadeusSystem/amadeus_tts.py`

## 2. データフロー（会話ループ）

1. **リスニング:** `amadeus_ear.py` はマイクを常時監視します。ユーザーが話し終えると、テキスト文字列（例: "おはよう"）を返します。
2. **思考:** メインループはこの文字列を`amadeus_core.py`に渡します。Brainはストリーミング方式でAPI（Groq）をクエリします。また、この際ChromaDBから引き出した記憶を一時的にコンテキストに注入・破棄します。
3. **発話:** LLMがテキストチャンク（例: "おはよう、助手。"）を生成すると、`amadeus_core.py`はこれらのチャンクを即座に`amadeus_tts.py`に渡します。
4. **再生:** `amadeus_tts.py`はそのチャンクの音声を生成し、Brainが残りの文を生成している間に再生します。

## 3. 開発フェーズ

### フェーズ4.5: コアループ
- Groq APIをラップする堅牢なPythonクラスとして`amadeus_core.py`を固める。
- ターミナルベースのテキスト会話がストリーミングおよびRAG（一時的コンテキスト注入）と完全に連携することを保証する。

### フェーズ5.1: 感覚統合（耳）
- Faster Whisperを使用して`amadeus_ear.py`を実装する。
- 耳 → 脳の接続（端末に話しかけると、Amadeusがテキストで応答）。

### フェーズ5.2: 発声統合（口）（完了）
- VOICEVOXを用いた非同期キュー＋PyAudioインメモリ再生アーキテクチャの構築（将来のGPT-SoVITSストリーミングAPIへの前方互換性を確保）。
- 脳 → 口の接続（LLMのストリーミング出力に追従した極低遅延の音声応答の実装完了）。

### フェーズ6: 完全なループの構築
- 耳 → 脳 → 口の接続を確立する。
- レイテンシの調整、中断処理、および全体を統括する`main.py`コントローラーの最適化を行う。
